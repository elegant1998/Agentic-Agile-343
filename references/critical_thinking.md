# 批判性思维（Critical Thinking · v1.15 硬性 · 跨项目通用）

> **适用范围**：**所有**使用本 skill 的项目、业务域与任务类型。
> **不是**：某个门户/课程/证书功能的局部补丁。
> **是**：OA 在 Specify / Constrain 阶段的**默认工作方式**——把模糊意图校准为可验证、可运营、成本合理的契约。

## 核心原则

1. **意图 > 字面**：听懂目标与约束，而不是复读用户措辞。
2. **先质疑，后编码**：存在可识别风险信号时，**禁止直接实现**。
3. **推荐默认 + 说明理由**：挑战时必须给出更合理的默认方案，并允许 IO 否决。
4. **可验证**：规则必须能挂到进度、AC、事件、计数等可观测信号上。
5. **可演进**：发现误实现后，改契约、反哺图谱 HX，而不是「将错就错」。

## 何时必须暂停实现、先挑战

出现任一信号时，**停止写代码**，先 Grill-Me（或等价的逐条确认）：

| # | 通用可疑信号 | 抽象模式（跨领域） | 校准方向 |
|---|--------------|-------------------|----------|
| 1 | **激励 / 凭证过密** | 每个微动作都发奖、记账、开凭证 | 绑定**可完成的阶段性成果**，控制熵增与存储膨胀 |
| 2 | **自然语言歧义** | 一句话可有两种以上产品语义 | **显式二选一**；推荐更可验证、成本更低的那种并写清理由 |
| 3 | **与北极星 / 既定契约冲突** | 新需求否定刚签过的规则或战略指标 | 指出冲突，请 IO 修订意图图谱/契约或撤回新需求 |
| 4 | **不可验证 / 不可自动化验收** | 无状态、无事件、无 AC 可测 | 要求补可观测信号后再实现 |
| 5 | **安全 / 权限过宽** | 无审批写生产、泄密、整库覆盖 | **直接拒绝**，给安全替代，不进入实现 |
| 6 | **局部最优、全局劣解** | 单功能方便、系统复杂度指数上升 | 给出系统级推荐（更少状态、更清晰边界） |
| 7 | **与刚确认的决策自相矛盾** | 短时间内规则翻转 | 引用既有契约/HX，请 IO 明确取舍 |

## 挑战话术模板（跨项目通用 · 必带推荐默认）

```text
⚠️ 需求校准（批判性思维 · 非拒绝）
【我理解的意图】：…
【按字面实现的风险】：…（歧义 / 熵增 / 成本 / 不可验证 / 安全 / 与北极星冲突）
【推荐方案】：…（默认；更可验证、更可持续）
【备选】：…（若坚持原表述）
请回复：推荐 / 备选 / 自定义
确认前不进入实现。
```

## 与 Grill-Me / SCOPE-V 的关系

| 阶段 | 批判性思维做什么 |
|------|------------------|
| Specify | 拆歧义、挑战激励密度、对齐北极星 |
| Constrain | 卡住不可验证与不安全规则 |
| Orchestrate 前 | 仍可 HITL 质疑；避免「已开工才发现做错」 |
| Evolve | 误实现后修正契约并反哺 **通用** HX 模式（不绑定业务专名） |

- **价值判断** → Grill-Me，不得静默按字面做。
- **禁止**：「用户说了 → 我照做 → 完成」而跳过本节。

## 反哺时怎么写教训（通用，不写死项目）

在意图图谱 HX 中记录**模式**，而非产品专有名词：

```text
| HX-… | 误把「阶段性完成」做成「每个微动作开凭证」 | 改为绑定可验证的阶段终点 | 激励熵增 / 存储膨胀 |
| HX-… | 自然语言可双解，未先二选一就实现 | Specify 先澄清 + 推荐默认 | 返工 |
```

（具体业务案例可写在**该项目**的 `Intent_Graph.md`，不必写进本 skill 正文。）

## Grill-Me 交互协议（HITL 提示词工程）

> **核心原则**：HITL 不应是"甩一份完整文档让 IO 通读"，而应是**逐条引导 IO 决策，每次只问一个问题，并给出推荐的默认答案**。
> **叠加 v1.14**：先运用**批判性思维**校准可疑规则，再 Grill-Me 逐条确认——对所有项目一律生效。

### 适用场景

所有需要 IO 决策的 HITL 点，必须使用 Grill-Me 协议，不得一次性抛出完整文档：

| HITL 点 | 当前反模式 | Grill-Me 正确做法 |
|---------|-----------|-------------------|
| 图谱节点提取确认 | 更新整份图谱 → 请审阅 | 逐条问："提取的北极星指标是 X，是否正确？[Y/n]" |
| 契约待确认事项 | 列在 §6 底部 → 等 IO 发现 | 逐条主动提问 + 推荐默认值 |
| 契约签署 | 甩 144 行文档 → 请签署 | 先逐条确认关键决策 → 汇总后**请 IO 显式签署**（OA 不得代签） |
| 约束矩阵 | 和契约一起甩 | 逐域确认：STRUCT/DATA/BEHAVE/QUAL/PROC |
| 证据包裁决 | 完整报告 + 请裁决 | 先汇报风险 → 推荐裁决 → 确认 |

### 协议格式

每次 HITL 交互必须遵循：

```
[当前阶段] → [决策点 N/M] → [推荐答案] → [简短理由] → [Y/n/自定义]
```

### 示例

**❌ 反模式（当前）**：
```
IO 你好，以下是 T-002 意图契约（144行），请审阅后签署。
[完整契约文档]
签署区: _________
```

**✅ Grill-Me 模式**：
```
📋 T-002 契约裁剪完成，请逐条确认以下关键决策：

Q1/5: 本阶段是否只做需求分析和架构设计，不写代码？
  [推荐: ✅ 是 — MVP 一周内，先设计再开发]
  Y/n?

Q2/5: 是否暂不对接外部 PMS 酒店管理系统？
  [推荐: ✅ 暂不对接 — 自建居住域，后续可集成]
  Y/n?

Q3/5: 食材溯源认证标准？
  [推荐: 🇨🇳 中国有机认证 GB/T 19630]
  中国/欧盟/美国?

Q4/5: MVP 上线时间约束？
  [推荐: ⏱️ 一周内]
  自定义天数?

Q5/5: 是否需要国际化/多语言？
  [推荐: ❌ 不做 — 先聚焦中文市场]
  Y/n?

---
以上 5 项确认后，OA 必须向 IO 展示**完整契约（含 §7 签署区）**，由 IO **显式签署**；此步骤不可自动完成，OA 不得代签。
```

### 关键规则

1. **每次只问一个问题**（或紧密相关的一组），不要让 IO 做多维度判断
2. **必须有推荐默认答案**，IO 可以一键确认（"Y"）
3. **默认答案基于图谱已提取的信息**，不是凭空猜测
4. **确认完毕后必须请 IO 显式签署**：展示完整契约的签署区，由 IO 主动确认（回复「签署」或填写署名）。**OA 不得自行代签或盖章。**
5. **IO 可以随时说"等等，让我看看完整文档"**，此时再展示详情

### 对话流状态机

```
IO 注入模糊意图
    │
    ▼
OA 提取图谱节点 ──→ Grill-Me 逐条确认 ──→ IO 确认/修正
    │
    ▼
OA 裁剪契约 ──→ Grill-Me 逐条确认 ──→ IO 确认
    │
    ▼
IO 显式签署 ──→ AS 进入 SCOPE-V
    │
    ▼
AS 执行完毕 ──→ OA 汇总证据
    │
    ▼
OA 汇报风险 ──→ Grill-Me 逐条 + 推荐裁决 ──→ IO 裁决
```

## 签署门（Sign-off Gate · 反代签）

> **核心区分**：**Grill-Me 决策确认 ≠ 契约签署（sign-off）**。两者是不同阶段、不同动作，不得混淆——粉丝踩坑正是把"逐条确认范围"当成了"已在契约上署名"。

### 两个动作必须分开

| 动作 | 是什么 | 谁做的 | 何时 |
|------|--------|--------|------|
| Grill-Me 决策确认 | 逐条确认范围 / 技术栈 / 北极星 / 边界等价值判断（如"MVP 只做需求分析不写码"） | IO 逐条拍板，OA 给推荐默认 | 契约裁剪阶段 |
| **契约签署（sign-off）** | 审阅**完整契约全文**，明确同意其作为本阶段**唯一可执行依据** | **IO 亲自**确认并署名 | Grill-Me 之后、编码之前 |

### 规则（硬性）

1. **OA 不得代签**：不得自行在契约中写入 `SIGNED`、IO 署名或"自动签署"标记。签署区的 `IO（意图主理人）` 一行必须由 IO 本人填写。
2. **先签后码（C-PROC-01）**：契约签署前不得创建任何业务代码。顺序严格为：Grill-Me 决策确认 → 展示完整契约 → **IO 显式签署** → 进入 Orchestrate 编码。
3. **签署动作必须显式**：OA 在 Grill-Me 确认后，须把完整契约（含 §7 签署区）呈现给 IO，并明确请求签署；IO 以「签署」/填写署名等明确动作确认。**沉默、未回复、或对单条决策回 Y 均不构成整体签署。**
4. **代签可被机械门拦截**：`gate_check.py --gate pre` 会扫描"自动签署 / 代签 / OA 代"等标记并直接判失败；签署区缺失或 IO 未署名同样失败。

### 正确做法示意

```
📋 以上 5 项已确认。现呈上完整契约 T-XXX（含 §7 签署区）。
请审阅全文后明确签署：回复「签署」或填写署名与日期。
签署后我将以此契约作为唯一可执行依据开始编码。
─────────────
[完整契约文档，含 §7 签署区，IO 署名留空待填]
```

> ⚠️ 若 IO 仅对 Grill-Me 逐条回复 Y/n、**未对完整契约做签署动作**，则前置门不通过，不得进入编码。

## HITL 触发条件

任一以下条件满足时，必须暂停 AS 自治，呼叫人类裁决：
