# 遥测扩展框架（P2 — 待自动化）

以下 4 个指标已定义度量框架。当前阶段建议在 SKILL.md 中记录采集方法，
手动录入 `collect_telemetry.py` 参数。待多项目积累 ≥5 个周期的实际数据后，
再考虑全自动化采集。

## 10.1 Agent 自主性等级（L1-L5）

参照自动驾驶 SAE J3016 标准的五级框架：

| 等级 | 名称 | 人类角色 | 核心度量指标 | 跃迁条件 |
|------|------|----------|-------------|----------|
| L1 | AI 辅助 | 编码者 | 采纳率、建议质量 | —（基线） |
| L2 | AI 协作 | 协作者 | 对话轮次比、覆盖频率 | —（基线） |
| L3 | AI 自主（受监督）| 审查者 | 审查通过率、干预频率 | 首次成功率 >70% + 覆盖率 >80% + 零高危漏洞 |
| L4 | AI 高度自主 | 监督者 | 升级率、独立成功率 | 目标准确率 >90% + 自愈率 >80% + 连续 10 任务无 HITL |
| L5 | AI 完全自主 | 策略制定者 | 业务成果关联、安全事件率 | 需跨项目验证 + 安全审计 + IO 特批 |

**采集时机**：每个 SCOPE-V 周期结束后评估一次。

**采集方式**：当前阶段手动对照上表判定，填入 `collect_telemetry.py` 的
`--autonomy-level L3` 参数（待新增）。自动化方案：积累 ≥10 个任务数据后，
通过 `autonomy_score` 综合评分自动建议等级。

## 10.2 提示词迭代时间（Prompt Iteration Time）

> 定义：开发者从首次发送 Prompt 到 Agent 输出满足需求的总耗时。

**度量公式**：
```
提示词迭代时间 = T(最终输出满足AC) - T(首次Prompt发送)
```

**关键洞察**：优秀的团队通过沉淀 Prompt 最佳模板库，能将此指标降低 40%-70%。

**衍生指标 — Prompt 模板复用率**：
```
模板复用率 = 使用模板的 Prompt 数 ÷ 总 Prompt 数 × 100%
```

**采集时机**：每个任务完成后记录。

**采集方式**：当前阶段建议在 Intent_Contract 的 `self_consistency` 字段中
增加 `prompt_iterations` 和 `prompt_template_used` 记录。自动化方案：
需要 IDE/CLI 插件级别的 instrumentation（埋点），不在纯脚本层面可解决。

**健康阈值**：
- < 10 分钟/任务：Prompt 工程成熟
- 10-30 分钟/任务：存在优化空间
- > 30 分钟/任务：沟通成本已抵消自动化红利

## 10.3 多智能体交接摩擦率（Agent-to-Agent Transition Overhead）

> 定义：在多 Agent 协同流水线中，上游 Agent 向下游传递上下文时的信息丢失率。

**度量公式**：
```
交接摩擦率 = 上下文丢失或降级的交接事件数 ÷ 总交接次数 × 100%
```

**上下文丢失判定标准**：
1. 下游 Agent 请求重新执行上游任务
2. 下游 Agent 产出与上游意图明显偏离（需人工判定）
3. 交接过程中需人工介入补充上下文

**采集时机**：每次多 Agent 协作任务完成后。

**采集方式**：当前阶段依赖 OA 在反思日志中手动记录交接质量。
`work_graph.yaml` 已定义了 DAG 交接边，可作为交接次数基线。
自动化方案：需多 Agent 运行时追踪，属于框架级能力。

**健康阈值**：
- < 10%：编排器成熟，多 Agent 协同顺畅
- 10%-30%：存在明显瓶颈，需优化 Agent 间协议
- > 30%：系统不可靠，建议回退单 Agent 模式

## 10.4 并行效率（Parallel Efficiency）

> 定义：实际并行度与理论最大并行度的比率。

**度量公式**：
```
并行效率 = 实际并行执行的任务数 ÷ 理论最大可并行任务数 × 100%
```

**理论最大并行度**：由 `graph_engine.py parallel` 命令输出。

**实际并行度**：实际同时执行的 Agent 数量。

**采集时机**：每次含并行组的 SCOPE-V 周期结束后。

**采集方式**：当前阶段通过 `graph_engine.py parallel` 获取理论值，
手动记录实际并发数。自动化方案：需要 Agent 运行时并发追踪。

**健康阈值**：
- > 80%：并行策略有效
- 50%-80%：存在资源争抢或调度延迟
- < 50%：并行组定义需要调整或增加资源
