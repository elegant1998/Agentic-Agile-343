## 说明

本矩阵定义项目的**硬门禁**。每项约束独立、可追踪、可被自动化检查验证。任何一条门禁未通过，项目不得视为完成。

**Enforcement 四级执行策略**：

| 等级 | 行为 | 适用场景 |
|------|------|----------|
| `block` | 当前变更不能进入下一阶段 | MUST 约束失败，硬性阻断 |
| `warn` | 记录风险，允许继续 | SHOULD 约束失败，风险可控 |
| `escalate` | 系统无法自行决定，暂停并提交 IO/OA 裁决 | 人工判断类约束、歧义规则、影响范围不明 |
| `log` | 仅记录，不告警 | MAY 约束失败，信息性记录 |

约束分为五个域：

| 域 | 含义 |
|----|------|
| **STRUCT** | 结构约束 — 文件、模块、接口必须存在且形态正确 |
| **DATA** | 数据约束 — 关键数据表示、类型白名单、字段合法性 |
| **BEHAVE** | 行为约束 — 核心逻辑必须满足的运行时行为 |
| **QUAL** | 质量约束 — 测试、覆盖率、性能阈值 |
| **PROC** | 过程约束 — 开发过程中必须遵守的纪律 |

## 冲突与优先级

### 优先级链

```
法律/安全约束 > 约束矩阵 > 已签署意图契约 > 实现便利性
```

### 冲突解决规则

1. **法律/安全约束**为最高优先级，不可被任何下层文件覆盖。
2. **约束矩阵**中标记为 `MUST` 的条款优先于意图契约中的任何冲突条款。
3. **已签署意图契约**中的条款优先于实现者的便利性选择。
4. 任何例外**只能**由人类 IO 通过签署的书面批准授予，必须记录理由、批准人和有效期。
