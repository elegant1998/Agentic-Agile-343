## 5. 自动化验收标准

每项验收标准必须可通过命令或测试脚本客观判定。`AC-` 编号唯一且不可变。

| ID | 类别 | 描述 | 验证方式 |
|----|------|------|----------|
| AC-001 | 测试数量 | 测试用例总数 ≥ [N] | `pytest --tb=short` |
| AC-002 | 测试通过 | 所有测试通过，0 failure | `pytest --tb=short` 退出码 0 |
| AC-003 | 覆盖率 | 核心代码行覆盖率 ≥ [X]% | `pytest --cov --cov-fail-under=[X]` |
| AC-004 | [类别] | [可客观判定的标准] | [具体命令] |

> **验证方式列的自动化前缀（v1.11+）**：`verify_contract.py` 可自动执行带前缀的 AC，
> 未带前缀的自然语言描述视为人工验证项（HITL 审查覆盖）：
>
> | 前缀 | 格式 | 示例 |
> |------|------|------|
> | `shell:` | 执行命令，退出码 0 通过 | `shell: npm run build` |
> | `http:` | HTTP 请求，检查状态码 | `http: GET /health expect 200` |
> | `assert:` | Python 表达式，True 通过 | `assert: len(routes) >= 5` |
> | `db:` | SQL 查询断言 | `db: SELECT COUNT(*) FROM users` |
>
> 注意：命令中含 `|` 管道符时，用反引号包裹整段（如 ``shell: `npm run dev 2>&1 | head -5` ``），
> 否则会被 Markdown 表格误切。
